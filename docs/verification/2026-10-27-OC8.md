## Result

- **Real home (signed in), success:** `opencode auth list` answered exit 0 with a plain-text table, two entries in this profile: a provider with source `environment` and a gateway entry with source `stored`. Structure only; no secret printed.
- **Real home, failure:** after two successes earlier on 2026-10-27, five consecutive attempts failed with stderr `Location plugins did not finish activating` (exit 1) — through both the `opencode.ps1` shim and the direct binary, with and without `--standalone`, from different working directories. No stray processes were left behind by the failures.
- **Scratch `OPENCODE_DB`/`XDG_*` (signed out):** exit 0 with a single entry whose credential source is `environment` — the environment-provided credential (`OPENROUTER_API_KEY`) still appears, so a true "signed out" case needs that variable removed from the child environment.
- **Exit code:** 0 when it answers; 1 on the plugin-activation failure.
- **SEC:** `opencode auth export` prints stored credentials **including secrets** — never call it (D5); `auth list` names providers only.
- **Candidate alternative for the adapter:** the managed-server route (`opencode serve` + HTTP; see the OC2 record for the working scratch pattern) with the protocol's credential/integration groups, or `--server` against a running instance. Not yet verified.
