# C07–C08 — working workspace and presentation

The real Windows desktop proof passes with three nested panes, split/move/hide,
keyboard resize, healthy terminal input/output, and layout reload retaining the
same three runtime IDs without starting processes. Hide and Show are acknowledged
by SQLite before the reload assertion. An early test read the previous debounced
save; the driver now waits for the exact revision and visibility state.

Terminal find scans the existing bounded scrollback in small frame slices, retains
at most 200 matching lines and leaves the emulator parser running. The native proof
finds real output, closes with Escape and restores the original terminal focus.
Drag previews and cancelled/invalid mutations preserve resource references; the
renderer reparents the same terminal elements and never restarts their processes.

Five frame skins and six versioned terminal profiles are implemented. Follow-skin
starts disabled. Font changes trigger fitting only when metrics change; colour
changes do not rewrite terminal bytes or resize a PTY. Unavailable profiles use
Neutral and fonts have a local monospace fallback. Preferences use one bounded
SQLite capability with revision CAS; future/malformed values remain preserved.
The native proof changes skin/font/follow-skin, confirms saving, reloads and verifies
the selected values with the same live terminal IDs. Borderless frame controls
remain operable above dialogs; close performs bounded preference/layout saving.

Essential evidence: frontend build, six model/persistence tests, five mocked UI
flows, two presentation tests, two SQLite preference tests, and the single combined
real desktop smoke. The later C09 resource readout uses cached measurements and is
qualified with its own final integration. Full agent/session/browser features and
release qualification remain separate steps.
