# C15 — first Claude TUI in the real Windows app

The final combined desktop proof passes: select a synthetic project, run healthy
contained PowerShell panes, start the private pinned sidecar, explicitly Check
Claude, open its original interactive TUI, stop it and close the application with
saved workspace/presentation preferences. No prompt answers, sign-in or model
message is automated. Runtime IDs and canonical `i_`/`t_` references are checked;
the Claude profile and actual 1 GiB job limit are visible in the app.

The installed CLI is **2.1.316**, 335469216 bytes, SHA-256
`e896a9d8da519353a49bf69ca4a695ba7e09067752687c675b3969041e632d52`.
Its private contained version-only probe passed in 8.589 s and released its native
job/reservation. Shinatama does not query authentication or read credential files;
the UI reports Unknown. The original CLI retains the user's sign-in interaction.

Check runs a separate canary with a fresh C01 temporary home/project. Only actual
owned PTY output, complete resource observations and verified Released cleanup can
produce its opaque startup receipt. Normal Open re-pins and hashes the executable,
checks the exact current FS03 boxed-home record/revision, verifies the same native
profile and live sidecar, composes C11 argv/environment/identity, and consumes its
single-launch permit. No shell wrapper, UI-supplied ready flag, recipe or token is
accepted. The default native host and generic registry stay closed without their
specific trusted context.

Scope is **CLAUDE_CODE_SAFE_MODE=1 with an empty set**, on this exact Windows build
and CLI fingerprint. It is a TUI-startup qualification, not provider coverage,
authentication, model response, resume/fork or other capability certification.
Managed policy hooks/statusline/file suggestions may still apply according to the
[official environment contract](https://code.claude.com/docs/en/env-vars).
The private startup summary keeps provider traffic and effective compression
configuration Unknown. The separate Sign-in button stays unavailable until its
operation is qualified; Open exposes the original TUI.

Frozen trial limits: 1 GiB job, 768 MiB per process, eight raw active processes,
10% machine CPU, 4 MiB/512 queue credits. Cleanup uncertainty retains the exact
owner and budget. Sealed native rundown fixes short-lived startup children without
releasing unknown/reopened jobs or changing these limits. Expected close-channel
disconnection is distinguished from queue overflow. Saved-view removal changes
layout references only; it never replays an old command.

Reproduction: frontend build; helper build; desktop build with custom-protocol;
`verify/P14/target/debug/p14-probe.exe wrap-run node apps/desktop/tests/desktop-smoke.mjs`.
The private fixture uses an ephemeral CDP port and explicit save acknowledgements.
`SHINATAMA_SMOKE_FIRST_AGENT_ONLY=1` selects the focused first-agent path.
Sanitized local logs are in `.verification/c15-desktop-live.log`; a separate native
sealed-rundown fixture, 10 job tests and 10 terminal tests cover its cleanup guards.

The local launcher is `Shinatama.cmd`; instructions are in `AVVIO.md`. This is an
implemented startup slice; incomplete V1 features and release gates remain open.
