## Diagnosi della prova live (perché il primo run falliva)

1. Run 1: `exact-claude-2.1.317-hash` → re-pin (sopra).
2. Run 2: il corpo upstream osservato dall'origine sintetica **non** conteneva
   il sentinel `<bili_output_steering>`, con `system` presente
   (`main-steering-system-present`, stage aggiunto alla fixture con soli codici
   fissi; nessun contenuto attraversa il canale).
3. Causa nel sorgente canonico (sola lettura, nessun fork): la fixture imponeva
   `CLAUDE_CODE_MAX_OUTPUT_TOKENS=128`; il sidecar classifica
   `max_tokens<=200` come **side request** e la inoltra in passthrough
   ("kernel state untouched", log `bili.log`), saltando output steering. Il
   gate `typeof body === "string"` in `server/relay.ts` esclude inoltre le
   corsie passthrough (Buffer) dallo steering.
4. Correzione nella sola prova: lo scenario `effective-config` usa ora
   `CLAUDE_CODE_MAX_OUTPUT_TOKENS=1024` (sopra la soglia side); gli altri
   scenari restano a 128. `evidence()` conta ora i proprietari per scenario
   (3 per effective-config: fixture, sidecar, un solo Claude main-lane).
