# C09R.4 — bounded native fault fixture

Status: targeted native execution passed on 2026-11-02, Windows 11 x64. Both test
entries passed; all eight fault rounds completed in 0.66 seconds. Every fresh
healthy-sibling ping met the frozen 750 ms deadline and the saved fixture stayed
intact. This document does not qualify full product resilience.

Run: `cargo test -p shinatama-engine --test resource_faults --offline -j1 -- --test-threads=1 --nocapture`.

The Windows test uses only its own test executable, private temporary directory,
minimal environment and native JOB_LIST binding before the suspended process is
resumed. DETACHED_PROCESS and explicit NUL/pipe handles avoid console hosts.
Budgets are fixture-specific, not production calibration: 128 MiB job commit,
64 MiB process commit, one active process, 1% machine CPU for the busy-loop case
and 10% for the other cases. No host exhaustion or provider/agent command runs.

Two rounds each exercise local commit refusal (4 MiB allocations, at most 24
attempts), CPU work without an event-loop response, refusal of one extra process,
and a finite 1 MiB producer on an anonymous pipe. The parent reads/discards at
most 32 KiB with a 4 KiB buffer, then leaves the producer under pipe backpressure.
The requested pipe size is 4 KiB; Windows documents this size as a suggestion,
so it is not claimed as a production hard queue ceiling.

Before, during and after each fault, a distinct ping token must be acknowledged
by the healthy sibling within 750 ms. Only the exact responsible owned job is
terminated; known process handles must signal within three seconds. A synthetic
saved file must remain identical. A process-limit refusal that leaves an
unverifiable lifetime census retains `Retired`, never a fabricated release proof.

Limits: this fixture qualifies native jobs and OS-pipe behavior only. It does not
qualify real ConPTY input, WebView/UI responsiveness, the product output queue,
monitor-process failure, adaptive host calibration or long-running release soak.
Those gates require their own integration evidence.

Primary semantics: [job limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information),
[VirtualAlloc](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualalloc),
[anonymous-pipe backpressure](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-createpipe).
