# BillionContext source provenance

Imported from the official MIT-licensed repository at exact commit `7e69b49ff4facb00b5ba6541b48d0f7fbe63d63d`, corresponding to npm version **0.1.207**, verified as latest on **2026-10-25** (previous baseline 0.1.196, `d64139f9`). `provenance.json` records the official archive SHA-256 and the upstream hash of each imported file.

Musashi Terminal owns this private source package. Its build retains Claude Code, Pi, Codex, Gemini CLI and OpenCode CLI routing plus their required injected entries. The source import follows that dependency closure and includes the upstream kernel and Pi subagents component. No Tritech fork or compiled BillionContext npm artifact is used. Local changes implement private paths, native Codex overlay isolation, disabled self-update, dynamic analysis/build compression profiles and automatic proxy recovery on the original address for active CLI sessions. The Musashi Terminal-owned adaptive modules additionally implement the historical Tri-Tech Code contextd compression policy on the existing proxy paths: a smooth usable-budget threshold, accepted-request growth and candidate deduplication, a shared UTF-8 material-saving gate, complete current-user wire-owner protection and byte-preserving response acceptance. Shipped defaults enable CCR and Absorb through the existing supported tool channels. These are local source adaptations, not an upstream version change. The root MIT license and both component licenses are retained. The optional jimp image encoder and mysql2 storage driver are absent from the runtime: image rescaling passes images through and storage uses the built-in SQLite engine.

Native prompt rewriting is another Musashi Terminal-owned adaptation: provider-bound catalog discovery, economical model selection, bounded editing, durable one-shot admission and wire-only guidance that preserves the original. It reuses Tri-Tech Code's editing instructions adapted from MIT Better Prompt 0.9.0; exact originals, license, commit and the 2026-10-17 upstream verification are in `src/musashi-terminal/prompt-rewrite/upstream.json`. No fixed Gateway/model, upstream agent pipeline or goal loop is introduced.

The prepared runtime retains the Better Prompt MIT notice as `BETTER-PROMPT-LICENSE` alongside its root BillionContext license.

Storage latency (2 November 2026): a save with 600 changed CCR entries and 200,000 unrelated messages blocked a real local CONNECT tunnel for 13.57 seconds. SQLite checked the content foreign keys by scanning entire referencing tables; every save also released and recreated all CCR blobs, including unchanged ones. The owned schema v9 adds indexes for all six content references without rewriting data. CCR ingestion now updates only changed rows and applies net reference-count changes, preserving shared blobs across reorder and key replacement. The same fixture completed CONNECT plus echo in 59–69 ms after the fix. `test/storage-latency.test.mjs` covers query plans, v8 upgrades, unchanged writes, shared references, rollback, successive edits and transport latency. Other synchronous engine work remains on the existing event loop; this change removes the demonstrated archive-size-dependent stall rather than asserting that every source of latency is eliminated.

Local review corrections preserve image-aware context accounting, fit optional rewrite notes into the active request budget, isolate auxiliary idempotency, follow the editor model’s token contract, retain ChatGPT-only Codex catalog entries and stop draft selection on a new textless human turn. These safeguards remain owned source adaptations; the upstream pin is unchanged.

The 20 October incremental-preparation adaptation changes the local kernel wire converters and default token estimator. Bounded exact-content caches reuse message projections and pure token estimates; current ordering, tool pairing, duplicate identifiers and wire layout are reconstructed for each request. Session-scoped preparation caches are disposable derived data, never authoritative history. The cold conversion path and compression protections remain available. These kernel edits are local changes relative to the recorded upstream hashes.

Review corrections protect unvisited projections from eviction during a history scan, prune entries absent from a completed pass and detach retained token-cache keys from their source strings, including on cache hits. These changes retain the existing entry and byte limits.

Reasoning-only turns that complete normally now receive a local neutral completion note across the four proxy protocols. Neither the compression loop nor the legacy optional Responses reasoning guard automatically continues such turns. Failures, output limits, tool calls, refusals and other non-text outputs retain their native outcome. The notice preserves provider usage and reasoning signatures.

Completion classification includes visible text in Anthropic block-opening events and uses filtered Responses text so removed internal markers cannot suppress the local note.

Claude context accounting corrections give the Claude 5 opus/sonnet/fable generation its native 1M standard window (Anthropic billed up to 660,831 input tokens without tier negotiation, while the 200K tier gate produced non-retryable preflight 502s), stop Anthropic Threads continuations — billed for the stored thread but estimated from their delta body — from teaching the estimate calibration, and discard calibration rings persisted by earlier builds on restore.

Anthropic Threads field inheritance: Claude Code's continue sends only the billing-attribution projection of `system` and omits unchanged `tools`, leaving both to the stored Thread. The Anthropic lane now forwards an inherited field exactly as the client sent it (no compress prompt, cache stamp, system anchor or ACP tools), keeps compress advice available when the inherited tools declared it, and leaves explicit continues on the unchanged injection path. Previously every session's first continue was rejected with "differing field(s): cache_control, system[, tools]" and Claude Code replayed the whole conversation.

A stored Thread keeps the additions the proxy forwarded at create, so the proxy records their digests per session. When a continue inherits a field whose additions changed since (a settings reload arming CCR, image compression, rules or absorb), it answers locally with `thread_not_found`, the error Claude Code replays on a new Thread without turning inheritance off; one change asks once. A missing record presumes the current additions. The projection is recognised from Claude Code's own rule (billing attribution and the "# Reporting outcomes" section) without session memory, and the decide side call no longer carries `thread`: it is stateless on a create and skipped on a continue, whose delta body lacks the history and whose target a side call would consume.

Anthropic Threads loop rounds: when the proxy runs one of its own tools on a continue turn, its re-request carries only the delta, which previously had no `cache_control`. Anthropic then read the stored Thread from cache only up to system and tools; on 20 October 2026, 86 such rounds averaged a 46% cache hit and re-billed 10.2M tokens. The delta now repeats round 1's last message breakpoint, client TTL included, on its last cacheable block.

Prompt-rewrite corrections (20 October 2026): the editor returns its edit between `<edited_request>` tags and any text outside them is discarded as an answer to the draft; backticked literals compare by content; capitals/punctuation-only edits add no note; a discarded edit reports its specific reason instead of `unchanged-or-invalid`; null Chat `function_call` fields are absent; unpriced lightweight candidates prefer the catalog's newest release over ID order. That day 63 of 67 attempts ended as `unchanged-or-invalid` and 43 used `claude-haiku-4-5-20251001` although `claude-haiku-5-5` was listed.

Foreign traffic (20 October 2026): a conversation request that reaches the proxy through the MITM tunnel is processed only when a launched client identifies itself — Claude Code by its session header or CLI user agent, Codex by its user agent, plugin-equipped agents by `x-bili-plugin`. Anything else, such as a script that inherited the session's `HTTPS_PROXY`, is relayed with its original bytes, logged once per host (`src/musashi-terminal/foreign-traffic.ts`, gate in `src/server/handle.ts`). That day 181 script requests to an OpenAI-compatible gateway had gained the compress prompt, the ACP tools and `<acp>` tags, and one was refused with the #286 identity error. Explicit `/bili/` and base-URL routes are unchanged.

Proxy cache breakpoints (20 October 2026): for Anthropic clients that set no `cache_control`, the proxy's message breakpoints were cumulative and stopped at three, on the premise that removing an earlier mark breaks the cached prefix. Claude Code itself moves its breakpoint every request at 95-100% cache hits, so the premise does not hold, and the cap left the newer history of such clients never written. Each request now writes at its last stable message and keeps the previous request's write point as its read point (`src/loop/cache-control.ts`). Messages keep the kernel's single block-array shape whether marked or not.

Live prompt-rewrite corrections (20 October 2026): on the Anthropic route the editor request carries the client billing-attribution block, without which a subscription credential answered 429 "Error" to every call (#2189 rule), and literals inside a backticked span still count, so a quoted `node tools/test-sidecar.mjs --context` is no longer a literal mismatch. Evidence: `docs/verification/2026-10-20-prompt-rewrite-live.md`.

Prompt-rewrite editor thinking (20 October 2026): the Anthropic editor turns thinking off with the value its own catalog entry declares as supported under `capabilities.thinking.types` (`disabled`, else `between_tools`), so no model name is matched; Sonnet 5.5 rejects `disabled` and accepts `between_tools`. In an interleaved live run, Haiku 5.5 timeouts at the 3 s budget fell from 8 to 2 of 42 calls. Evidence: `docs/verification/2026-10-20-prompt-rewrite-live.md`.

Prompt-rewrite notes in the past (20 October 2026): the derived note was attached only after the last human, so on the next human turn it vanished from the previous turn and the provider re-billed everything after that human. Notes already decided for earlier humans are now recalled from the session (no catalog, admission or completion) and attached again with the same bytes after the same owner; only the current note stays optional. Results are kept up to the admission cap instead of the last 128, because an evicted result would change the past on every later turn. The proxy test now keeps sessions and dumps in its temporary root instead of the live directories a Musashi Terminal shell exports.

Epochs (20 October 2026): on adaptive sessions with a known capacity the past changes only when a frontier moves (`src/musashi-terminal/epoch.ts`, the rule of Tri-Tech Code's `billion-flow/core/frontier.ts`), measured on the history as it arrives less the savings of accepted folds. `src/stream.ts` `applyRanges` and `src/absorb.ts` `executeAbsorb` return a neutral receipt below the first frontier and keep accepted changes pending inside an epoch, with the fold-time storing of covered originals (#1179) deferred to the landing; both run under `src/musashi-terminal/turn-refusals.ts`, which closes them for the human turn after repeated refusals, and `src/loop/core.ts` ends a round that only calls closed tools. `src/decompress-shared.ts` carries its inline-restore flag to the pending state; `src/loop/core.ts` skips the second-round re-fold (#422) and consumed-call hiding on these sessions; the four `src/server/prepare-*.ts` apply absorb views, subagent notes and summary/reasoning removal only up to the frontier and tell the turn whether compress is injected and nudges are on. Kernel adaptation: `kernel/src/packs.ts` no longer invites proactive compression ("Compress when an ACP nudge invites it").

Advisory nudge removed (20 October 2026): with the frontier the adaptive advice (`Adaptive context:` notes, candidates, accepted-growth history and the relay's acceptance observer `src/musashi-terminal/adaptive-acceptance.ts`) had no reachable use; `src/musashi-terminal/adaptive-turn.ts` keeps only the frontier path and falls back to the ordinary kernel turn, the four `src/server/prepare-*.ts` render the kernel nudge directly, and `src/server/relay.ts` no longer observes acceptance.

Upstream 0.1.207 (25 October 2026): a three-way merge against the 0.1.196 baseline. 120 files changed only upstream were taken as published, 34 locally adapted files were merged, the two image-compression modules upstream removed were dropped and 56 new upstream modules entered the import closure. Local decisions on new upstream behavior: Claude Code's auto-mode safety classifier is no longer answered locally unless `BILI_AUTO_MODE_FORGE=1` or `autoModeForge.enabled` asks for it (`src/knobs.ts`; upstream #2740 forges an allow verdict by default); upstream's byte-faithful Anthropic Threads lane (#2926) is kept but not routed (`src/server/prepare-anthropic.ts`), so Threads turns stay on the inheritance path above; the GitHub changelog fetch (`src/web/changelog.ts`) and the runtime SQLite engine download (`src/storage/engine-bootstrap.ts`) are disabled like self-update; the shipped defaults keep full-text absorb (`mediaOnly: false`; upstream #3402 limits absorb to image-bearing results by default). Merge adaptations: the incremental projection cache stores each message's new `wireIndex`, follows the Responses system/developer head rule (#4166) on cached items, keeps the new multi-core layout slots and keys tool results on their resolved call name, which #3642 now seeds into result identity; the Thread addition digests include the lane-decision system variant and the client tools' code-mode note. `src/optional-modules.d.ts` declares the omitted jimp and mysql2 modules for the type check.

Busy proxy (31 October 2026): a shared proxy held its event loop for 71 seconds while keeping its port. Every session's recovery monitor counted it dead after two missed 1.5 s health checks. Each monitor started a replacement that lost the bind with the twin-collision exit and then printed its attempt over the Claude Code screen; 170 replacements started that day. `src/musashi-terminal/proxy-recovery.ts` now treats a missed health check on a port that still accepts TCP connections as busy: nothing is started, and a spell longer than 15 s is reported once, with its end reported once too. `src/launcher.ts` wires the check to `tcpConnectable`. Once a quiet launch (`MUSASHI_TERMINAL_BILI_QUIET=1`) starts supervising, it mutes the launcher's stderr leg and sends its log lines and spawn-wait warnings to the host log.

Owner renewal output (1 November 2026): the first fix missed one caller. The supervising monitor renews its watcher ownership through `registerWatcherDefault`, which wrote `bili: watcher registration failed ... (The operation was aborted due to timeout)` with a bare `console.error` over the Claude Code screen whenever the busy proxy missed its 2 s window. `registerWatcherDefault`, the attach-gate refusal in `pickAttachable` and the three stale-rotation messages in `rotateStalePredecessor` now use `launchWarn`, which prints before the client starts and writes to the host log after. The remaining `console.error` calls in `src/launcher.ts` run before the client starts or after it exits. `test/proxy-recovery-launcher.test.mjs` runs the default registration against an unreachable proxy and asserts the terminal stays empty.

Proxy stalls (1 November 2026): two paths turned a busy proxy into `ECONNREFUSED` for Claude Code. First, the shared proxy shut itself down while its owners were alive: after holding its event loop for about 36 s its owner watchdog found all six heartbeat owners past the 15 s grace on its first tick, logged `watchers-gone (...) [stale-heartbeat pids: ...]` and force-exited with 324 connections open (four such shutdowns that day). The watchdog tick moved from `src/server.ts` into `src/musashi-terminal/watchdog-stall.ts`, which credits a late tick's delay beyond one interval back to every recorded heartbeat and to the idle grace; `watcherIsDead` and the 15 s/5 s graces are unchanged. Second, on Windows a listener whose loop is held refuses new connections once 232 wait to be accepted (Node 24, measured; unchanged with backlog 2048), so the monitors' TCP check read the busy proxy as gone and their probe connections filled the queue. `src/musashi-terminal/proxy-recovery.ts` now asks a bind attempt first (`src/musashi-terminal/port-held.ts`: `EADDRINUSE` means held, no queue slot used), falls back to the TCP check only when the bind cannot decide, and probes a busy proxy at a growing interval up to eight intervals. `src/launcher.ts` wires the bind check, injectable as `LauncherDeps.isPortHeld`.

Encrypted Chat reasoning replay (2 November 2026): the OpenAI Chat wire codec retains `reasoning_details` as opaque metadata, including reasoning-only assistant messages, exact owner boundaries and cached projection. The stream adapter forwards proof-only frames and proof beside intercepted tools; the loop collects textual fragments while preserving opaque entries whole and replays the proof on internal tool continuations. Compress-round reasoning cleanup retains such proof. Token estimates exclude encrypted payload bytes and the core metadata copy. Both `openai-native-responses-v1` and `openai-responses-v1` are retained without translating provider formats. Evidence: `docs/verification/2026-11-02-encrypted-reasoning-replay.md`.
