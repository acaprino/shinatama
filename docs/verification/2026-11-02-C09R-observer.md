# C09R.1 — bounded native and window observations

2026-11-02, Windows local verification passed: **37 engine tests**, Clippy with
warnings denied, frontend/desktop builds, formatting and dependency inventory.
The real app observed its host and owned WebView processes while remaining responsive.

The frozen 12-second fixture observed 110 complete snapshots, 13 monitor cycles
and eight processes. UI roundtrip p95 was **7.47 ms**, maximum **8.98 ms** (limit
1500 ms); maximum whole observer cycle was **27.15 ms**, counter reads **0.81 ms**.
These are measurements on this machine, not hard native-call deadlines or workload
budget calibration. No pressure, OOM, agent launch or paid provider call was used.

The sampler distinguishes private commit, summed resident pages, CPU time and
system commit/physical headroom. Exact PID+FILETIME creation identities prevent
PID reuse and double counting. Missing, denied, exited, regressed and group-mismatched
counters remain explicit. At most 256 processes and 120 frames/60 seconds are held.
Resident totals can count shared pages more than once and are not unique physical RAM.

One background worker discovers bounded owned ancestry without inspecting executable
names or opening files. Known live orphans remain tracked; uncertain discovery is incomplete.
Native reads occur outside shared locks and the UI thread. One report slot and
non-blocking reads prevent queue growth; stopping never joins a blocked native call
or starts a replacement worker while its slot remains occupied.

The embedded app exposes numeric status only. Window telemetry measures input
dispatch delay, peak frame interval per reporting window and IPC roundtrip, without
reading keys or terminal/document contents. One IPC report can be in flight;
hidden windows discard stale frame/input samples. Workload/terminal queue counters
are currently `null`, not fabricated zeroes; their owners must instrument them when
the admission/terminal components are connected. Owned descendants are not labelled
as a host/renderer baseline until workload job membership is registered.

adaptive intervention, queue integration and fault recovery are **not qualified**
