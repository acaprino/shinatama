# TL1 — embedded Tauri shell on Windows

Date: 2026-11-02. Scope: the shell proof of technical-design 3.1 and ADR-0005 v3.
This fixture is not the shipped terminal-first interface or a pass of TL2–TL6.

## Environment and result

Windows 11 x64 build 26200; actual attached WebView2 **156.0.4314.58**;
native Claude Code **2.1.316**. The proof executable embeds its frontend assets,
with `tl1-proof,custom-protocol` explicitly enabled. No development server was
started. Node/Playwright drive the test externally; the app's descendants contain
the app, its WebView2 processes, PowerShell and ConPTY, with the native Claude
process observed while the interactive checks run. No Node or external browser
process is required by the shell.

The valid run passed real local file navigation, bounded UTF-8 reads, inert
Markdown source/preview, native interactive Claude and its local `/help`, nested
pointer/keyboard resizing with unchanged session identity and a live Claude
process, verified `/exit`, and a responsive shell afterwards. File navigation
re-reads an externally changed synthetic file. Traversal, alternate data stream,
oversized and binary reads are rejected. The preview executes no supplied HTML
and issues no remote content requests.

The final nested ratios match their displayed keyboard values within one
percentage point at all three levels. Three Rust tests for relative paths,
bounded UTF-8 file reads and bounded directory listing also passed.

Commands, from the repository root:

```powershell
npm run build:tl1
npm run desktop:tl1
verify/P14/target/debug/p14-probe.exe wrap-run node apps/desktop/tests/tl1/proof.mjs
```

The test-only file commands are compiled behind `tl1-proof`; the regular build
has neither these commands nor the fixture assets. Rebuild the regular frontend
and debug executable before regular desktop tests:

```powershell
npm run build
cargo build -p shinatama-desktop --features custom-protocol
```

## Evidence and limits

The fixture writes bounded, sanitized `result.json` and a post-agent screenshot
under ignored `.prototype-evidence/tl1/`. Raw terminal output and native account
presentation are not saved. The only screenshot is taken after verified agent
exit and screen clearing. A sanitized final result is retained with this record.

The final driver submits no model prompt: it uses native local `/help` and
`/exit`, then verifies the Claude process is absent before sending PowerShell
probe commands. An earlier failed driver sent its shell probe after an unverified
Ctrl+C exit; it may have been interpreted as an agent prompt. That run is **not**
qualified as having submitted no model prompt and does not supply the pass.
The subsequent driver correction is preserved in the fixture and its README.

Windows without WebView2 has not been tested. Installer/runtime handling remains
an ADR-0048/release qualification gap. The proof renderer implements inert
headings, paragraphs, lists and fenced code only; complete Markdown, Mermaid,
document fidelity, hostile-content grants and document editing remain later
gates. The P14 wrapper contains the test run; this does not qualify production
process containment, resource-pressure resilience or any RES gate.

Build infrastructure initially failed under host commit-memory exhaustion, and
an initial driver misclassified the Tauri IPC origin as a remote preview request.
These failures were corrected before the valid shell run; no toolkit fallback
or architectural shell failure was hidden.
