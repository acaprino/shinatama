# C03M.1 — bounded maintenance core

Date: 2026-11-02. Scope: the shared-state library's maintenance core. Automatic
desktop scheduling and the healthy-terminal integration belong to C03M.2/C03M.3.

The core runs on its own existing-database connection, never the foreground
connection and never `CREATE`/migration mode. Its initial ceilings are 128 rows,
64 KiB admitted record payload, approximately 50,000 SQLite VM instructions and
a cooperative 100 ms for the SQL work/finalization/lease-cleanup slice after
filesystem admission. Admission duration is measured separately; a soft 500 ms
check defers SQL after a slow preflight returns. Callers may reduce work limits,
not raise the ceilings.
[SQLite progress callbacks](https://www.sqlite.org/c3ref/progress_handler.html)
interrupt SQL work; filesystem operations and native I/O have no hard deadline.
The 100 ms value is not an end-to-end runtime guarantee.

Header/size admission precedes record validation. A legitimate record larger
than the current batch is reported as unverified with a bounded reference; it is
not mislabeled malformed and cannot permanently block later records. Anomalies
aggregate identifiers/reason/count only, with no copied work or credentials.
Two reserved operational settings hold bounded metadata; authoritative projects,
settings, agent archives and migration backups are never automatically deleted.

Admitted work includes periodic `quick_check`, bounded `optimize`, incremental
vacuum only if already enabled, and size-admitted PASSIVE checkpoints. A skipped
or interrupted integrity check does not certify integrity or imply corruption.
Schema names/DDL are projected with byte and row ceilings before Rust copies
them. SQLite's own schema parsing and OS allocations are not a measured C09R
native-memory guarantee.

A private crash-released file lock and an expiring PID/creation-time/token lease
prevent overlap. Future/read-only schemas receive no job writes. Fresh version
checks inside write transactions protect an already-open older connection when
another window upgrades the archive. Pressure/cancellation defer optional work.
Typed writes also check a fixed 4 GiB storage envelope, 1 MiB write reserve and
64 MiB free-space floor. These checks do not reserve space against arbitrary
other writers; C09R supplies aggregate resource admission.

The shared mutation token gives cancellation and entering commit a single atomic
winner. Cancel never waits for filesystem work or promises to undo a commit that
already won. Prepared filesystem paths are separated from SQL-only selection,
allowing compound project/history updates to use one transaction.

Qualification passed on the supported Windows host: **72 tests** (18 library,
15 database, 13 location, 19 maintenance, 7 migrations), plus Clippy with warnings
treated as errors. The exact command selects these targets explicitly:

```powershell
cargo test --offline -p shinatama-state --lib --test database --test location --test migrations --test maintenance --example check_location -j1 -- --test-threads=1
cargo clippy --offline -p shinatama-state --lib --test database --test location --test migrations --test maintenance --example check_location -j1 -- -D warnings
```

The independent review found and prompted regression coverage for lost scan
progress after an interrupted optional check and unbounded schema materialization.
The 5,000-record and 2,000-VM-budget fixtures now demonstrate durable progress
across newly admitted ticks. Version-race tests cover lease claim, state save and
lease release after a second connection upgrades the archive. Cancellation and
commit have one winner; oversized legitimate rows do not starve later records.
The runtime scheduler and wider RES gates are not declared delivered by these
library tests.
